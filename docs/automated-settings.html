Enforce mode

Automated settings

This is the complete list of what the script changes for you in Enforce mode. Every change is shown with the current and the new value, and nothing is applied until you approve it. Discover mode only reads these settings and changes nothing.

Audit logUsers & guestsApp consentBreak-glassSign-in methodsSharePoint & OneDriveDevices & IntuneDefenderConditional AccessIntune policiesPurviewWipeChecked, not changed

1. Unified audit log

Needed for investigations, Defender and Purview.

SettingWhat the script sets
Unified audit log ingestionOff → On. On a new tenant it first runs the one-time Exchange tenant preparation, then turns the log on. It can take Microsoft up to 60 minutes before the log shows as On.

2. Users and guests (Entra)

Default user permissions and guest access, set to the secure reference.

SettingWhat the script sets
Users can register applicationsNo
Users can register agent identity blueprintsNo (when your tenant exposes the setting)
Restrict non-admin users from creating tenantsYes
Users can create security groupsNo
Guest user access restrictionsLimited access to properties and memberships of directory objects
Security defaultsTurned on only when the tenant has no Conditional Access policies, so it is never left without MFA

3. App consent

SettingWhat the script sets
User consent for appsOnly apps from verified publishers with low-impact permissions
Admin consent request workflowEnabled, with reviewers you choose (the account running the script, another account, or both), requests valid for 30 days

4. Break-glass accounts

Existing break-glass accounts are detected and checked first. Missing parts are created.

ItemWhat the script does
Two break-glass accountsCreates svr_ea_01 and svr_ea_02 on your onmicrosoft.com domain with strong generated passwords
Global Administrator roleAssigns the permanent Global Administrator role to both accounts
Security groupCreates the break-glass security group and adds both accounts
Restricted management administrative unitCreates it with restricted management turned on and puts the group inside

5. Sign-in methods

MethodWhat the script sets
Passkey (FIDO2)Enabled
Microsoft AuthenticatorEnabled
Temporary Access PassEnabled
SMSDisabled
Voice callDisabled
Email one-time passcodeDisabled

6. SharePoint and OneDrive sharing

SettingWhat the script sets
External sharing levelNew and existing guests (sign-in required)
Guests can share items they do not ownNo
Guests must sign in with the account that was invitedYes
Legacy authentication protocolsBlocked

7. Devices and Intune

SettingWhat the script sets
Automatic Intune enrollment (MDM user scope)All users, or a pilot group if you give one
Microsoft Entra Local Administrator Password Solution (LAPS)Enabled
Require multifactor authentication to register or join devices (legacy setting)No
Global administrators become local admin on Entra-joined devicesNo
Registering user is added as local administrator on joinNone

8. Defender

SettingWhat the script sets
Defender for Office 365 Standard and Strict preset protection rulesEnabled when they exist but are off
Intune connection to Defender for EndpointConnected for Windows, Android, iOS and macOS (when the connector exists)

9. Conditional Access baseline

Deploy all policies at once or one by one.

ItemWhat the script does
ALSO Conditional Access policiesImports them switched off, so nothing blocks sign-in until you test and enable each one
Groups and authentication contexts the policies needCreates the missing ones
Break-glass groupAdded as an exclusion to every Conditional Access policy
ALSO Conditional Access groupsPlaced inside the restricted management administrative unit

10. Intune policy baseline

ItemWhat the script does
Compliance, app protection, BitLocker, local admin rights, Defender and Edge policiesImported from ALSO's templates, unassigned, so you decide who gets them

11. Microsoft Purview

ItemWhat the script does
Sensitivity labels for Microsoft 365 groups, Teams and sitesOff → On
Sensitivity labels for SharePoint, OneDrive and PDF filesOff → On
ALSO Purview baselineCreates or updates sensitivity labels, the label policy and DLP policies (DLP starts in simulation mode so nothing is blocked by surprise)
7-year Exchange retention policyOptional. Only deployed if you explicitly confirm it, because mail is deleted after 7 years

12. Wipe: undo what was deployed

Wipe mode lists what was deployed and you choose what to remove. Your own policies, groups and labels are never touched.

AreaWhat can be removed or set back
Break-glassThe two accounts, their group and the restricted management unit
Conditional Access, Intune and PurviewThe ALSO baseline items that Enforce deployed
Tenant-wide settingsUser settings, app consent, SharePoint sharing, LAPS and Intune enrollment can be set back to Microsoft defaults

• Checked, but changed by you

These appear in the report's Manual checks and actions tab with a link to the right place.

  • Restrict access to the Microsoft Entra admin center, LinkedIn account connections and "Show keep user signed in" (Microsoft offers no way to set these automatically)
  • SPF, DKIM and DMARC for your domains (recommendations with guide links, never changed)
  • Default sharing link type, link expiry and OneDrive-specific sharing level
  • Reviewing, testing and switching on the imported Conditional Access policies
  • Defender for Identity, Defender for Cloud Apps, incident notifications and access reviews
