Secure by Default

ALSO Secure by Default is an automated discovery and deployment script that reads and configures security foundations, such as tenant-wide settings, Intune policies, Conditional Access policies, and Purview policies that are already part of ALSO's Microsoft Security policy templates.

It helps new tenants start securely from day one and can also be used by existing tenants to discover and deploy selected policies.

Read the report and review all recommended actions and guidance to help establish a secure-by-default environment.

Why Secure by Default

A secure foundation is what every other security control, and every Copilot rollout, stands on. Audit logging, emergency access, strong sign-in methods, device enrollment and sensible tenant defaults decide whether policies actually protect you, and whether you can investigate when something goes wrong. Getting them right from day one, on new and existing tenants, prevents gaps that are hard to see later.

🔍

Discover before enforce

Default mode is strictly read-only and produces a drift report against the reference state.

🧭

Guided step by step

Each change is numbered, explained and confirmed. Answer “all” to apply the rest, or “skip” to stop changing.

🎯

License aware

Reads your licenses first and only recommends what fits: everything for E5/E7 or security suites, no Defender for Identity or Cloud Apps for E3, F1, F3 and Business Premium, and no Intune or Defender products for Business Basic and Standard.

📋

One clear report

Two tabs: Automated checks and actions, and Manual checks and actions. Each item explains why it matters, what changes from what to what, and links to the portal and the ALSO guide. Filter by needs action, OK or info.

🗃️

Works on existing tenants

Lists the Conditional Access, Intune and Purview policies you already have, ALSO or not, flags identical duplicates and never changes policies it did not create.

🧹

Wipe what was deployed

Run -Mode Wipe to undo a test or a rollout. Matches only the exact ALSO names, asks per category and needs you to type WIPE. It can also set tenant-wide settings back to Microsoft defaults, and you choose which.

🛡️

Safe by design

Run the script from your own controlled environment, such as an admin workstation or a secured jump host. It uses your interactive Global Administrator sign-in, runs locally, and keeps reports on your machine.

How it works

Connect

Sign in interactively in your browser (up to four sign-ins: Microsoft Graph, Exchange, Purview and SharePoint). Each one is explained first, and Discover only asks for read access.

Discover

Compare the tenant with config/reference-state.json. Nothing changes.

Review

Open the HTML report; adjust the reference to fit your organization.

Enforce

Confirm each change, all at once or one by one, including each Purview part. A summary shows what changed, failed and still needs a person.

Wipe (optional)

Remove what the script deployed: Conditional Access and Intune policies, Purview items, tenant-wide settings (back to Microsoft defaults) and the break-glass accounts. Choose all, one by one or none per category. Your own objects are never touched.

Get started

A Global Administrator account is required for all steps. PowerShell 7 or later is required (Windows PowerShell 5.1 is not enough). Download it from aka.ms/powershell and run the script from a PowerShell 7 window opened as administrator. On first run, approve the permission request for the “Microsoft Graph Command Line Tools” enterprise application.

# if scripts are blocked: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
git clone https://github.com/CoC-MS/ALSO-Microsoft-Security-SecureByDefault
cd ALSO-Microsoft-Security-SecureByDefault

# 1. discovery (read-only)
./scripts/Invoke-SecureByDefault.ps1

# 2. guided enforcement
./scripts/Invoke-SecureByDefault.ps1 -Mode Enforce

# 3. optional: remove what the script deployed
./scripts/Invoke-SecureByDefault.ps1 -Mode Wipe
