Why Secure by Default

ALSO's JSON configuration files cover policies and baselines. Some prerequisites live outside them: tenant switches, emergency access, authentication methods, enrollment and connector state. This tool closes that gap.

🔍

Discover before enforce

Default mode is strictly read-only and produces a drift report against the reference state.

🧭

Guided step by step

Each change is explained and confirmed. Supports -WhatIf for dry runs.

🛡️

Safe by design

Passwords are never logged or written to reports; risky policies start in report-only.

⚙️

Best-supported tooling

PowerShell with Microsoft Graph, Exchange Online and SharePoint modules — the only stack covering all workloads. Pairs with Microsoft365DSC for drift control.

How it works

Connect

Sign in interactively with least-privilege scopes (read-only in Discover mode).

Discover

Compare the tenant with config/reference-state.json. Nothing changes.

Review

Open the HTML report; adjust the reference to fit your organization.

Enforce

Confirm each change. Re-run any time to verify compliance.

Get started

Requires PowerShell 7+ and a Global Administrator (or equivalent) account. Modules install to the current user on demand.

git clone https://github.com/CoC-MS/ALSO-Microsoft-Security-SecureByDefault
cd ALSO-Microsoft-Security-SecureByDefault

# 1. discovery (read-only)
./scripts/Invoke-SecureByDefault.ps1

# 2. dry-run selected steps
./scripts/Invoke-SecureByDefault.ps1 -Mode Enforce -Steps AuditLog,Fido2 -WhatIf

# 3. guided enforcement
./scripts/Invoke-SecureByDefault.ps1 -Mode Enforce
